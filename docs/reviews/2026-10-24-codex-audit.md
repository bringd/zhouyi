## 结论与优先顺序

图鉴的基本数据和正常跳转可用；问题主要在**古文/释义校勘、异常路径处理、八宫的展示顺序和查阅效率**。建议先修内容与异常路径，再做目录和视觉调整。

通过的部分：

- 64 个 ID、64 种卦形均唯一；八卦组合与六爻阴阳一致；按爻变规则独立核对，64 卦的八宫归属和本宫/世次/游魂/归魂角色一致。
- 浏览器逐一打开 64 个有效详情页，标题、主卦六爻图形及六个爻辞指示器均符合本地数据。
- 三套外观 × 主题/八宫两种模式 × 320/390/1440 三档尺寸，共 18 组，现有 DOM 探针未检出字号、正文对比度、目标尺寸和横向溢出失败。
- 现有 485 项测试全部通过，前端类型检查和 Worker 构建通过。**这些测试通过不能证明古文和释义正确**，现有文本测试主要检查非空及篇幅。

## 已确认错误及功能问题

### C1：乾卦存在明确内容错误，应优先校正

源文件：[hexagrams.json](D:/eight/src/data/hexagrams.json:16)。

| 位置 | 当前内容 | 校正依据与建议 |
| --- | --- | --- |
| 乾卦《彖传》 | 大明**始终** | 通行本为“大明**终始**”。[臺大周易哲学课程原文讲义，第 2 页](https://ocw.aca.ntu.edu.tw/uploads/course_item_file/file/738/103S201_AA03L01.pdf) |
| 乾卦现代解读 | 纯阳之卦，**三爻**皆阳 | 此页展示六画重卦，应为**六爻**；三画乾卦与六画乾卦在这里混淆。讲义也明确说明乾卦整体的六个阳爻。 |
| 乾卦九三释义 | 处下卦之终、**位不当** | 按通常爻位规则，九三为阳居阳位，问题在重刚不中、处下体之极，不应直接写成失位。[《周易象义》九三释文](https://www.shidianguji.com/book/CADAL02041514/chapter/1lmo0ghef72nn) |

三处文字均已在实际详情页中复现，不只是数据文件里的闲置字段。位置分别在源文件第 16、85、49 行。

### C2：损卦六三原文漏字

[hexagrams.json](D:/eight/src/data/hexagrams.json:3679) 写作 `三：三人行……`，应为 `六三：三人行……`。页面虽然会根据爻位另画“六三”徽章，但正文原文仍不完整。参考[张载《横渠易说·损》](https://www.shidianguji.com/book/SK0013/chapter/1loz760hy1q2b)。

建议增加全部 384 爻的爻位称谓与阴阳匹配校验。本次独立检查发现的称谓不匹配为这一处。

### C3：小象数据有批量误填风险，展示之前必须校勘

去掉标点和爻位前缀后，384 条 `xiaoXiang` 中有 **85 条与对应爻辞完全相同**。这 85 条是待核查清单，不能直接当作已逐条确认的 85 个错误。

抽查损卦已能确认多条错填，例如：

- 六四的小象写成了整句爻辞，应为“损其疾，亦可喜也”。
- 六五的小象也写成了整句爻辞，应为“六五元吉，自上祐也”。
- 六三的小象混入了爻辞及“言致一”的说法，与通行本“一人行，三则疑也”不符。
- 上九的小象结尾写为“无所疑也”，通行本为“大得志也”。

证据位于 [hexagrams.json](D:/eight/src/data/hexagrams.json:3650)，参照[《横渠易说·损》](https://www.shidianguji.com/book/SK0013/chapter/1loz760hy1q2b)。

当前详情页**没有渲染小象原文**，因此这些错误目前主要属于资料层风险。应先按可靠底本校勘，再接入页面；不能直接把现有字段全部展示出来。

### C4：非法详情编号会使整个应用空白

[HexagramDetail.tsx](D:/eight/src/pages/HexagramDetail.tsx:52) 用 `parseInt()` 直接调用会抛错的 `getHexagramById()`。后面的 `if (!hexagram)` 无法接住异常，根应用也没有错误边界。

实际复现：

- `/hexagram/0`：整页空白，控制台 `No hexagram with id 0`。
- `/hexagram/1abc`：被误认成第一卦并正常展示。

建议严格校验完整编号为 1–64 的整数，非法编号显示“未找到该卦象”和返回入口；另添加页面级错误兜底。若重排代码，还应让 Hook 调用保持稳定，避免把 `useMemo` 放在条件返回之后。

### C5：八宫模式采用了文王卦序数字排序，未展示八宫内部卦次

八宫归属数据正确，问题在 [CodexGrid.tsx](D:/eight/src/components/sections/CodexGrid.tsx:125) 的 `sort((a, b) => a.id - b.id)`。

乾宫当前显示：乾 → 否 → 大有 → 观 → 剥 → 遁 → 晋 → 姤。

若此模式用于讲解传统八宫，应显示：乾 → 姤 → 遁 → 否 → 观 → 剥 → 晋 → 大有，即本宫、一世至五世、游魂、归魂。八个宫的当前内部排序均没有采用这个角色顺序。宫组顺序也只是数据首次出现的顺序。

依据：[中国孔子网《八宫说》](https://www.chinakongzi.org/baike/MINGCI/zhexue/201708/t20170825_142776.htm)。

建议固定宫组顺序，按 `palaceRole` 排列卡片，同时显示角色标签。若产品有意保留宫内的文王卦序，应明确注明，避免用户将其当作八宫卦次学习。

### C6：“收藏本卦”实际上是下载图片

[HexagramDetail.tsx](D:/eight/src/pages/HexagramDetail.tsx:208) 的按钮调用 `handleDownload`，只导出 PNG，没有保存收藏列表或写入卦册。

这属于文案与行为不一致。可直接改为“下载卦象卡”，或真正实现收藏并提供可找回的收藏入口；这两种行为应分开命名。

### C7：浏览状态不能保留

[CodexGrid.tsx](D:/eight/src/components/sections/CodexGrid.tsx:19) 只在组件内保存模式。实际操作：八宫 → 乾卦详情 → 浏览器返回，页面恢复为主题分类，卡片数从 64 变为 113。

建议将模式、搜索条件和选定分组放在 URL 参数中，并恢复阅读位置，方便连续查阅和分享。
