## 一、产品定位

### 1.1 一句话

> 一个以《周易》六十四卦为核心内容，以精致国风动漫（工笔重彩 + 现代极简）为视觉形式，结合用户地区日期生成"今日卦境"、支持"三数起卦"和 AI 深度解读的**周易文化研究与自我反思网站**。

### 1.2 核心价值主张

- **文化研究**：完整呈现《周易》64 卦的卦辞、彖传、象传、爻辞和现代解读
- **日常仪式**："今日卦境"为用户提供每日一次的文化体验入口
- **互动起卦**："三数起卦"让用户通过数字主动探索卦象
- **AI 增强**：在预生成的高质量解读基础上，提供 AI 个性化深度解读

### 1.3 MVP 范围

**必须做：**
- 5 个核心页面：首页（含今日卦境）/ 64 卦图鉴 / 卦象详情 / 三数起卦 / 起卦结果
- 64 卦完整内容：卦辞 + 彖传 + 象传 + 6 爻辞 + 现代解读（共 1024 条原文 + 64 段现代文）
- 今日卦境自动生成（基于日期 + 地区种子）
- 三数起卦 + AI 增强解读（用户记录 LocalStorage 保存）
- 64 卦主题分类图鉴 + 八宫可切换

**暂不做：**
- 用户账号系统（用 LocalStorage 替代）
- 社区/评论/分享
- 复杂付费/订阅
- 高级统计与用户画像
- 大规模 3D 场景

## 二、技术架构

> **架构修订（2026-06-02 中期）：** 原"无后端纯前端 MVP"方案**已废弃**。项目确认部署到云服务器，因此采用**全栈架构**。原 LocalStorage 仅作离线缓存；AI 解读改为后端代理（费用由服务者承担，不再 BYOK）。

### 2.1 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite 5 | 启动快、HMR 体验好、包体小 |
| 前端框架 | React 18 | 生态最成熟、组件库丰富 |
| 样式 | Tailwind CSS 3 | 快速迭代、易维护 |
| 动画 | Framer Motion 11 | 声明式动画、与 React 无缝集成 |
| 路由 | React Router 6 | 简单稳定 |
| 状态 | Zustand | 轻量、够用 |
| 后端框架 | Node.js + Express + TypeScript | 与前端共享 TypeScript、部署简单 |
| 数据库 | PostgreSQL | 成熟稳定、支持 JSONB、适合结构化数据 |
| ORM | Drizzle ORM（或 Kysely） | TypeScript 原生、轻量 |
| 认证 | JWT（HttpOnly Cookie）| 无状态、安全 |
| AI | 后端代理 Claude API（Key 服务端管理） | 服务者承担成本、用户无摩擦 |
| 限流 | express-rate-limit + Redis / in-memory | 防止滥用 |
| 离线缓存 | LocalStorage（前端） | 网络断时仍可浏览卦象 |
| 部署 | 暂未决定（云服务器 / PaaS 备选） |  |
| 字体 | 霞鹜文楷（正文）+ 思源宋体（标题）+ 等线（数字） | 兼顾工笔气质与可读性 |

## 四、视觉设计系统

### 4.1 设计风格基线

**风格定位：** E 工笔重彩 + 现代极简（宋画小品 + 现代插画师国潮新韵）
**核心特征：**
- 矿物质色调色板（朱砂、石青、赭石、藤黄、墨色）
- 留白 + 透气感（信息密度宁少勿多）
- 现代极简排版 + 古典工笔视觉
- 印章作为视觉点缀（每页右下角 1-2 个）
- 拒绝：写实风 / 黄符纸 / 算命摊 / 过度暗黑

## 六、核心业务流程

### 6.1 今日卦境生成

```
[用户访问首页]
   ↓
[获取 Intl.DateTimeFormat 当前日期 + 地区 + 时区]
   ↓
[生成当日种子 = hash(YYYY-MM-DD + 用户时区)]
   ↓
[seed % 64 = 本卦 ID]
[seed % 6 + 1 = 动爻]
   ↓
[根据本卦和动爻计算变卦]
   ↓
[从预生成文案库读取基础解读]
   ↓
[渲染首页]
```

**关键点：**
- **确定性**：同一用户、同一日期、同一时区，看到的卦象完全相同
- **地域差异**：不同时区的用户看到的"今日卦境"可能不同（这是有意的设计——你身处不同时区，宇宙对你的"指引"不同）
- **无后端**：所有计算在前端完成

### 6.2 三数起卦

```
[用户输入 3 个三位数 + 可选问题]
   ↓
[校验：每个数 100-999]
   ↓
[计算]
  - 下卦 = A % 8 (0 → 8)
  - 上卦 = B % 8 (0 → 8)
  - 动爻 = C % 6 (0 → 6)
   ↓
[通过 (上卦, 下卦) 查表得本卦 ID]
[本卦 + 动爻 → 变卦 ID]
   ↓
[保存到 LocalStorage]
   ↓
[读取预生成基础解读]
[可选：调用 Claude API 生成 AI 深度解读]
   ↓
[渲染结果页]
```

### 6.3 AI 解读增强

```
[用户点击 "AI 深入解读" 按钮]
   ↓
[检查用户是否设置了 API Key]
   ↓
[是] → 跳过此步
[否] → 弹出输入框，提示用户输入 Claude API Key
       → 加密存储到 LocalStorage
   ↓
[构造 Prompt]
  - 系统提示：你是周易研究助手...
  - 上下文：本卦名、卦辞、动爻、变卦、用户问题
  - 要求：输出 6 个段落（卦象概要/当前状态/变化原因/后续趋势/行动建议/风险提醒）
  - 约束：不预测绝对结果、不替代现实决策
   ↓
[调用 claude-haiku-4-5 (成本最低)]
   ↓
[流式输出（SSE）]
   ↓
[保存到 LocalStorage]
```

**Prompt 模板（精简）：**

```text
你是周易文化研究助手，正在为一位普通用户解读一次起卦结果。

【卦象数据】
本卦：{mainHexagramName}（{mainHexagramJudgement}）
动爻：第 {movingLine} 爻（{movingLineText}）
变卦：{changedHexagramName}（{changedHexagramJudgement}）
用户问题：{userQuestion}

【输出要求】
请以现代人易理解的语言，分 6 段输出（每段 80-120 字）：
1. 卦象概要
2. 当前状态
3. 变化原因
4. 后续趋势
5. 行动建议
6. 风险提醒

【语气约束】
- 不使用"一定会"、"注定"等绝对化预测
- 不承诺具体结果
- 不替代现实决策
- 用"周易文化研究中一种可能的解读是..."、"这个卦象提示..."等学术化语气
- 鼓励用户结合自己的实际情况判断
```

## 九、错误处理

### 9.1 用户输入错误

- 三数起卦：每个数 100-999，超出范围给红色提示
- 问题文本：限制 200 字内

### 9.2 数据错误

- 卦象 JSON 加载失败：显示降级 UI，提示刷新
- 关系计算错误：降级到只显示本卦

### 9.3 AI 调用错误

- API Key 缺失：提示用户输入
- API Key 无效：提示检查
- 网络错误：3 次重试 + 降级到预生成解读
- 超时（30s）：降级到预生成解读
- 速率限制：提示用户稍后再试

### 9.4 LocalStorage 错误

- 配额超限：清理最早 20 条记录
- 隐私模式：提示功能受限
