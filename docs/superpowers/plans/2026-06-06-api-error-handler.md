# api-error-handler Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a Claude Code user-level skill (`api-error-handler`) that, when invoked, asks qwen3.5-omni-plus-realtime to diagnose API errors and suggest retry parameters. Total footprint: 2 files + 1 npm dep.

**Architecture:** Two files in `~/.claude/skills/api-error-handler/`. `qwen-call.mjs` is a ~110-line Node.js helper that connects to DashScope Realtime WebSocket, sends error context, prints qwen's response. `SKILL.md` is a ~50-line instruction file telling Claude when and how to invoke the helper. No hooks, no auto-retry, no tests in v1 (per spec).

**Tech Stack:**
- Node.js 18+ (uses `for await` on streams)
- `ws` 8.x (only dependency)
- DashScope Realtime WebSocket API (Alibaba Cloud)

**Spec reference:** `docs/superpowers/specs/2026-06-06-api-error-handler-skill-design.md`

**Out-of-git note:** The skill files live at `~/.claude/skills/api-error-handler/` (user-level), which is OUTSIDE the `D:\eight` git repo. Tasks use "verify" steps instead of `git commit` for skill files. The plan document itself lives in git.

**TDD note:** Per spec ("YAGNI tests in v1"), no automated tests. Each implementation task ends with a manual smoke-test step that uses the `Bash` tool.

### Task 2: Implement qwen-call.mjs

**Files:**

- [ ] **Step 1: Write the file**

Create `~/.claude/skills/api-error-handler/qwen-call.mjs` with this exact content:

```javascript
#!/usr/bin/env node
// qwen-call.mjs — api-error-handler helper
// Connects to DashScope Realtime WebSocket, sends error context to
// qwen3.5-omni-plus-realtime, prints the response on stdout.
// Fail-open: any internal error → stderr warning + exit 0.

import WebSocket from 'ws';

const API_KEY = process.env.DASHSCOPE_API_KEY;
const MODEL = process.env.QWEN_MODEL || 'qwen3.5-omni-plus-realtime';
const WSS_URL = `wss://dashscope.aliyuncs.com/api-ws/v1/realtime?model=${MODEL}`;

const TOTAL_TIMEOUT_MS = 60_000;
const FIRST_DELTA_TIMEOUT_MS = 15_000;
const HANDSHAKE_TIMEOUT_MS = 10_000;

const SYSTEM_INSTRUCTIONS =
  'You are an API error diagnosis assistant. Given error context, return ONLY valid JSON in this exact shape: ' +
  '{"diagnosis": "<short cause>", "category": "rate_limit|auth|network|server_error|client_error|unknown", ' +
  '"retryable": <bool>, "suggested_modifications": {<obj>}, "confidence": <0.0-1.0>}. ' +
  'No prose, no markdown fences, no commentary.';

if (!API_KEY) {
  console.error('api-error-handler: DASHSCOPE_API_KEY not set, skipping');
  process.exit(0);
}

async function readStdin() {
  if (process.stdin.isTTY) return '';
  const chunks = [];
  for await (const chunk of process.stdin) chunks.push(chunk);
  return Buffer.concat(chunks).toString('utf8');
}

const flagContext = process.argv.find(a => a.startsWith('--context='));
const context = flagContext !== undefined
  ? flagContext.slice('--context='.length)
  : await readStdin();

if (!context.trim()) {
  console.error('api-error-handler: no context provided (use --context=... or pipe stdin)');
  process.exit(0);
}

const ws = new WebSocket(WSS_URL, {
  headers: { Authorization: `Bearer ${API_KEY}` },
  handshakeTimeout: HANDSHAKE_TIMEOUT_MS,
});

let fullText = '';
let firstDeltaReceived = false;
let settled = false;

const totalTimer = setTimeout(() => {
  if (settled) return;
  settled = true;
  console.error('api-error-handler: total timeout exceeded');
  ws.close();
  process.exit(0);
}, TOTAL_TIMEOUT_MS);

const firstDeltaTimer = setTimeout(() => {
  if (firstDeltaReceived || settled) return;
  settled = true;
  console.error('api-error-handler: no first delta within timeout');
  ws.close();
  process.exit(0);
}, FIRST_DELTA_TIMEOUT_MS);

function cleanup() {
  clearTimeout(totalTimer);
  clearTimeout(firstDeltaTimer);
}

ws.on('open', () => {
  ws.send(JSON.stringify({
    type: 'session.update',
    session: { modalities: ['text'], instructions: SYSTEM_INSTRUCTIONS },
  }));
  ws.send(JSON.stringify({
    type: 'conversation.item.create',
    item: {
      type: 'message',
      role: 'user',
      content: [{ type: 'input_text', text: context }],
    },
  }));
  ws.send(JSON.stringify({ type: 'response.create' }));
});

ws.on('message', (data) => {
  let msg;
  try { msg = JSON.parse(data.toString()); } catch { return; }
  if (msg.type === 'response.text.delta') {
    firstDeltaReceived = true;
    fullText += msg.delta || '';
  } else if (msg.type === 'response.text.done') {
    if (settled) return;
    settled = true;
    cleanup();
    process.stdout.write(fullText + '\n');
    ws.close();
    process.exit(0);
  } else if (msg.type === 'error') {
    if (settled) return;
    settled = true;
    cleanup();
    console.error(`api-error-handler: qwen error: ${msg.error?.message || 'unknown'}`);
    process.exit(0);
  }
});

ws.on('error', (err) => {
  if (settled) return;
  settled = true;
  cleanup();
  console.error(`api-error-handler: ws error: ${err.message}`);
  process.exit(0);
});

ws.on('close', () => {
  if (settled) return;
  settled = true;
  cleanup();
  console.error('api-error-handler: ws closed unexpectedly');
  process.exit(0);
});
```

### Task 5: Write SKILL.md

**Files:**

- [ ] **Step 1: Write the file**

Create `~/.claude/skills/api-error-handler/SKILL.md` with this exact content:

```markdown
---
name: api-error-handler
description: When an API call fails (HTTP 4xx/5xx, ECONNREFUSED, ETIMEDOUT, 401/403/429), call qwen3.5-omni-plus-realtime for diagnosis and retry-parameter suggestions. Use when an API error needs a second-opinion diagnosis before retrying or giving up.
---

# When to use
- A tool call (Bash, WebFetch, MCP) returned an API-shaped error: HTTP status code, ECONNREFUSED, ETIMEDOUT, 401/403/429, 5xx, etc.
- You're about to give up on a request and want a second opinion on what to try next.

# When NOT to use
- Business-logic errors ("user not found" from your own DB lookup).
- Syntax / compile errors.
- Test failures unrelated to API calls.
- Anything where reading the error message is enough to know what to do.

# How to invoke
Run the helper via Bash. Either pass the error as `--context`:

```bash
node ~/.claude/skills/api-error-handler/qwen-call.mjs --context "<error text here>"
```

Or pipe the error text via stdin:

```bash
echo "HTTP/1.1 429 Too Many Requests" | node ~/.claude/skills/api-error-handler/qwen-call.mjs
```

# Output interpretation
The helper prints qwen's response on stdout. qwen is instructed to return JSON:

```json
{
  "diagnosis": "<short cause>",
  "category": "rate_limit|auth|network|server_error|client_error|unknown",
  "retryable": true | false,
  "suggested_modifications": {
    "timeout_ms": 60000,
    "headers": { "X-Example": "value" },
    "retry_interval_ms": 30000
  },
  "confidence": 0.0
}
```

# Decision guidelines
- If `retryable == false` or `confidence < 0.7`: report to user, do NOT retry.
- Apply `suggested_modifications` only if the keys are in the allowlist:
  - **Allowed:** `timeout_ms`, `headers`, `retry_interval_ms`, `method`
  - **NEVER apply:** `path`, body fields, resource IDs, auth tokens.
- If the JSON is malformed or the helper output is non-JSON: show the user the raw output and ask what to do.
- If the helper prints a warning to stderr (e.g., "DASHSCOPE_API_KEY not set"), treat the original error as the source of truth and proceed without qwen's input.

# Reporting to user
After acting on (or ignoring) the suggestion, summarize in 3 lines:
1. **Cause** — one line from `diagnosis`.
2. **Change** — diff between the original call and the retried call, or "no change — qwen's suggestion was rejected because <reason>".
3. **Result** — what happened on retry (or "did not retry" with reason).
```
